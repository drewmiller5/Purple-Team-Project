## Summary

- **1 High** — `wazuh.manager`'s `wazuh_active_response` volume + nested custom AR script bind-mounts (lines 216, 241-244) reproduces the K6 bug class in a second, still-unfixed location. Needs the same overlay-routing fix K6 got, or explicit from-scratch verification that it's actually harmless given all current AR bindings use `<location>local</location>` (which dispatches execution to the *agent*, i.e. `target`, not the manager) — that caveat is exactly why this is reported as an unresolved risk rather than a confirmed live failure.
- **1 Ambiguous/Low-confidence** — `wazuh.dashboard`'s `wazuh-dashboard-config` volume + nested `wazuh.yml` bind-mount is the same shape but matches upstream `wazuh-docker` verbatim; reported per the "ambiguous case gets reported, not dropped" instruction, not because there's positive evidence of a problem.
- **3 Info/Verified-clean** rows: all other `docker-compose.yml` mounts, `pytest.ini` (testpaths confirmed correct via directory scan + a live 130-test `--collect-only` run), and all four Dockerfiles in scope.
